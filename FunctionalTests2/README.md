**FunctionalTests2 — FINTECH 545, Fall 2026**

This folder is a standalone Python implementation of all 25 functional cases in groups 8–13. It includes the `risk545_ft2` package, 17 input CSVs in `data/`, 25 instructor output CSVs in `reference/`, and three instructor specification files in `source/`. It does not require the other assignments or a Julia installation.

| Cases | Calculation |
|:--|:--|
| 8.1–8.6 | Normal and Student t VaR/ES, including simulated t risk |
| 9.1 | Portfolio VaR/ES with fitted margins and a Gaussian copula |
| 10.1–10.4 | Risk parity, risk budgets, and bounded maximum Sharpe portfolios |
| 11.1–11.2 | Realized asset and factor return/volatility attribution |
| 12.1–12.3 | European GBSM Greeks, American CRR Greeks, and cash-dividend American options |
| 13.1–13.9 | Kendall correlation, multivariate t fitting, copula likelihoods/selection, tail dependence, and t-copula portfolio risk |

From this folder, create a Python 3.12 environment and install the pinned dependencies and local package:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install --no-deps -e .
```

Run the calculations, verify their saved results, and run the numerical tests:

```sh
python run_functional_tests.py
python verify_results.py
python -m pytest -q
```

The runner uses seed `545` and `100000` simulated paths for cases 9.1 and 13.9. Cases 8.3 and 8.6 use the instructor's fixed `10000` draws. The runner prints a case summary and exits with a nonzero status if a comparison fails. `verify_results.py` checks the bundled instructor-file hashes, completed-output hashes, schemas, and numerical comparisons without repeating the simulations.

Optional runs can choose a seed, output directory, path count, or complete groups from 8 through 13:

```sh
python run_functional_tests.py --seed 2026 --output-dir output_seed2026
python verify_results.py --output-dir output_seed2026
python run_functional_tests.py --groups 10 11 12 --output-dir output_portfolios_options
python run_functional_tests.py --simulations 200000 --output-dir output_200000
```

`--simulations` must be at least `10000` and affects cases 9.1 and 13.9. `--data-dir` and `--reference-dir` accept alternative input and comparison folders. Repeated runs can replace an output folder previously generated by this program; otherwise, choose an empty or new directory.

Groups 8–12 also produce 16 legacy filename aliases, such as `testout_8.1.csv`, because `Tests.xlsx` uses those older spellings. Each alias contains the same calculated table as its canonical counterpart. A group selection calculates only the selected groups and reads only their input CSVs. It writes the selected cases and their applicable aliases. Saved verification checks case coverage, aliases, counters, numerical comparisons and summary consistency.

The numerical conventions follow the instructor's generator and library routines:

- Normal fits use the sample standard deviation with denominator `n-1`. Location-scale Student t margins use maximum likelihood in inverse degrees of freedom with `nu >= 2.0001`. A fitted Normal limit is represented by `nu=inf` in the public API. JSON diagnostics record a null degrees of freedom and an explicit Normal-limit flag. The t scale differs from standard deviation for finite degrees of freedom.
- Empirical VaR uses the average of the `floor(n*alpha)` and `ceil(n*alpha)` ordered observations with one-based indexing, clamped to the first observation where necessary. ES averages the lower tail including observations tied at this threshold. Outputs express VaR and ES as losses.
- Python and Julia generate different random streams. Cases 8.3, 8.6, 9.1, and 13.9 therefore use statistical comparisons, with standard errors estimated from 20 batches. The teacher used `N_ref=10000` univariate draws and `N_ref=100000` portfolio draws. For our `N` draws, the estimated combined standard error is `own_MCSE*sqrt(1+N/N_ref)`, accounting for sampling error in both results. The reference limit is six times that combined error, or `6*sqrt(2)*MCSE` at equal path counts. Comparisons with analytic marginal risk use `6*MCSE`. These are approximate Monte Carlo checks conditional on the fitted model. Reports retain every actual difference and limit.
- Group 10 reads the supplied matrices directly as covariance inputs. Risk budgets specify proportions of component volatility. `Tests.xlsx` lists `test5_2.csv` for 10.3–10.4, but `test_setup.jl` and the reference outputs use `test5_3.csv`; this implementation follows the generator. That matrix is indefinite and is used directly, with positive variance required at evaluated feasible portfolios. Zero-risk starts are skipped when positive-risk portfolios are available, and a detected feasible null-risk portfolio with positive excess return is reported as an unbounded problem. Maximum-Sharpe diagnostics report the smallest eigenvalue and convergence across multiple starts; indefinite problems do not receive a general global-optimality guarantee. The instructor optimizer returns some weights approximately `1e-8` outside the stated bounds. Calculated weights obey the bounds; comparison uses a `3e-7` absolute optimizer tolerance plus the declared relative tolerance.
- Group 11 drifts weights as a buy-and-hold portfolio, links period return contributions with Carino's geometric-return adjustment, and attributes sample volatility using component covariance with portfolio return divided by portfolio volatility. Return and volatility contributions each add to their corresponding portfolio total. The factor-attribution weights input is `test11_2_weights.csv`, correcting the worksheet typo.
- Group 12 preserves two Greek conventions. European rho changes `r` and carry `b` together, holding dividend yield `q=r-b` fixed; European theta is calendar decay `-dV/dT` per year. American-tree rho holds `b` fixed; its theta is maturity sensitivity `+dV/dT` per year. Vega is per absolute volatility unit. The American Greek tree uses 500 steps and a $1.50 spot bump for gamma. Cash-dividend trees use two steps per maturity day and consider exercise immediately before payment.
- Group 13 uses the course rank/profile estimator: sample means and sample standard deviations, `R = sin(pi*tau/2)` from Kendall's tau with correlation repair, and two successive 200-point searches in `theta=1/nu`. This is distinct from jointly maximizing all multivariate t parameters. The reported t scale matrix `S` satisfies `covariance = nu/(nu-2)*S`. Copula model selection counts the Gaussian copula's additional profiled parameters as zero and the t copula's as one, following the source convention.

Public functions accept changed inputs. For example:

```python
from risk545_ft2.portfolios import maximum_sharpe

weights, diagnostics = maximum_sharpe(
    [[0.04, 0.01], [0.01, 0.09]],
    [0.08, 0.12],
    risk_free=0.03,
)
```

Other reusable functions are available in `distributions`, `risk`, `portfolios`, `options`, and `copulas`. Each case-building module provides `build_cases(data_dir, *, simulations=..., seed=...)`, returning calculated DataFrames and diagnostics. The calculation modules read input data only; they do not read reference outputs or substitute stored answers. Reference comparisons are handled separately by `risk545_ft2.validation.validate_cases`.

`SOURCE.json` pins the instructor repository to commit `b2b73187ddb47418ff5b20508065d34d858146a5` and records the source paths, Git blob IDs, and SHA-256 hashes of all 45 bundled instructor files. The implementation is based on those teacher files; the copies in `source/` preserve the workbook, Julia generator, and additional group-13 specification for review.
